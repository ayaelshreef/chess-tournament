# Ranking and tiebreaks

Verified on 19 November 2026 against:

- [Reference tournament, final crosstable](https://s1.chess-results.com/tnr1477698.aspx?lan=1&art=4&fed=LBA&SNode=S0).
- [FIDE C.07, effective 1 March 2026](https://handbook.fide.com/chapter/TieBreakRegulations032026), Articles 6, 8.1, 9.1, 15 and 16.
- [Swiss-Manager release history](https://swiss-manager.at/downloadhist.aspx?lan=1), including its March 2026 update for the new unplayed-round rules.

## Verified configuration

The reference lists Direct Encounter (DE), Buchholz Tie-Break Variable (2026) (Gamepoints), then Sonneborn Berger Tie-Break Variable (2026) (Gamepoints). No cut or median modifier is listed. “Variable” is the software's configurable tiebreak name; it does not itself specify a cut.

The application uses points (1 / 0.5 / 0), then those three criteria. Wins are retained as internal statistics for compatibility, but never break a ranking tie. Names only order the display of players sharing the same rank. Unresolved first-place ties still require the existing playoff.

DE evaluates the whole equal-points subset. Complete mini-tables split by encounter score, recursively reapplying DE to remaining tied subsets. Repeated encounters contribute their average. Incomplete mini-tables separate a leader only when that player is guaranteed to finish alone first under every possible missing result; DE is then reapplied to the remainder. Swiss forfeits are excluded. BH and SB apply separately inside the unresolved subsets. DE's displayed scores are contextual, not a globally sortable number; `/` separates recursive mini-table scores, and `—` means DE was inapplicable.

## Unplayed rounds

Normal results remain `white`, `draw`, `black`; `null` means awaiting a result. Additional saved result codes are:

| Result | Points, white / black | Treatment |
| --- | --- | --- |
| `white-forfeit` | 1 / 0 | Forfeit win / loss |
| `black-forfeit` | 0 / 1 | Forfeit loss / win |
| `double-forfeit` | 0 / 0 | Two forfeit losses |
| `bye` (no opponent) | 1 | Pairing-allocated or full-point bye |
| `half-bye` (no opponent) | 0.5 | Requested half-point bye |
| `zero-bye` (no opponent) | 0 | Requested zero-point bye / withdrawal |

For opponents' tiebreaks, trailing requested byes followed only by voluntary unplayed rounds become draws. Other awards retain their actual values. For a participant's own unplayed round, the dummy score is their actual total, capped by the scheduled opponent's adjusted total for forfeits, or half the tournament's round count for non-paired byes. SB multiplies each contribution by the points actually awarded that round. Unplayed games contribute no played color or DE encounter.

The school tournament has four rounds, so its bye cap is 2, including in provisional standings. Unfinished scheduled games are omitted until a result is entered; future ungenerated rounds add nothing. An absent player in a stored round is treated as having a zero-point bye. Existing stored ordinary games and automatic byes need no migration. Previously recorded ordinary wins cannot be inferred to have been forfeits; the organizer must explicitly select the correct result.

The latest-round editing restriction remains in place. A generated bye can be changed to a requested half/zero bye, but the pairing generator still allocates full-point byes automatically and its matching algorithm is unchanged. These result options do not introduce a withdrawal or availability management system.

## Reference crosstable discrepancy

The public reference is sufficient to verify the listed tiebreak sequence, but it does **not** reproduce every numerical value under the current FIDE text when its `-0` entries are interpreted as zero-point byes. The test fixture preserves all 31 public round records and published totals, using final-row numbers as anonymous IDs. All points agree; BH/SB differ on 15 rows.

For example, row 25 has one point and a zero-point bye in round 7. Article 16.3.2 makes that last-round bye a draw solely for opponents' tiebreaks, giving an adjusted score of 1.5. Row 10 beat row 25. Its FIDE BH/SB are consequently 27 / 13, whereas the published values are 26.5 / 12.5. This difference follows directly from the documented rule; no hidden cut can be inferred from the public labels.

The differences affect ordering too: applying the verified FIDE rules swaps rows 14/15, 17/18 and 26/27 relative to the published table. The reference's DE column also uses its own display encoding; this application displays mini-table scores instead.

The original organizer's tournament file and any event-specific Article 16.6 overrides would be needed to explain these differences conclusively. The application follows the published FIDE 2026 definitions rather than introducing undocumented exceptions to mimic the reference's numbers. The regression test explicitly records the differences; it does not claim an exact numerical reproduction.
